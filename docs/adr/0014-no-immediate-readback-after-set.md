# 0014. SetC 後の即時読み戻しを行わない

- ステータス：承認
- 日付：2026-11-20

## コンテキスト

Set_Res は SetC 要求に対する応答だが、プロパティ値の変更完了を示すものではない。
機器内部の状態が変わるまでの時間は一定とは限らず、Set_Res 後の固定時間を待って
GET しても、変更前の値が返ることがある。

状態変化時アナウンスプロパティマップに含まれる EPC は、初期通知要求に対して実際に
通知が確認できれば、以後の状態変更を INF または INFC で受け取ると仮定する
（ADR-0009）。通知が確認できない EPC は、通常のポーリング対象となる。

## 決定

- Set_Res 後に、固定時間を待って GET する機能を設けない。
- Set_Res で受理された値は、これまでどおりキャッシュに反映する。
- その後の実状態は、受信した INF / INFC または通常の GET 応答でキャッシュに反映する。
- ポーリング対象の選択と周期は既存の規則を維持する。SetC を契機とする即時読み出しは行わない。

## 結果

- SetC ごとの追加 GET がなくなり、通知が確認された EPC への重複した読み出しを避ける。
- Set_Res 後の読み戻しが変更前の値を返し、キャッシュを一時的に巻き戻すことがなくなる。
- Set_Res 直後は受理された要求値がキャッシュに反映されるため、内部状態が変化する前に
  キャッシュ値が実状態より先行する可能性は残る。後着の通知またはポーリングで実状態に合わせる。
- 通知が確認されない EPC は、次回の通常ポーリングまで実状態の反映が遅れることがある。
