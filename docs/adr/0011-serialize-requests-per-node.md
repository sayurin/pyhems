# 0011. 要求をノードごとの直列キューで送り、setup をイベント処理から切り離す

- ステータス：承認
- 日付：2026-11-01

## コンテキスト

pyhems が機器に送る要求には、次の経路がある。

- setup の GET（プロパティマップと監視対象の EPC の初期取得）と、その後の INF_REQ（`0x63`）
- 範囲が未設定の計測値リストを初期化する SetC（ADR-0008）
- 定期ポーリングと即時ポーリングの GET
- 呼び出し側の任意の GET（`HemsClient.get`）と SetC（`set_properties`）

これらは互いに調整されておらず、同じノードに同時に要求が届くことがある。同時応答数に制約のある機器（ADR-0001、ADR-0003、ADR-0007）では、同時に届いた要求が無視されたり、上限の学習を乱したりする。

また、setup・INF_REQ・範囲の初期化は、受信イベントを順に処理するタスクの中で待っている。setup は 1 回の要求で最大 30 秒待ち、応答がなければ半分に分けて再送する（ADR-0004）ので、応答の遅い機器が 1 台あると数分かかる。その間、ほかのノードの受信フレームも処理されず、ポーリングの応答が届かないものとして失敗に数えられる。ADR-0004・ADR-0005・ADR-0006 は、この問題と setup の並列化を範囲外としていた。

ADR-0005 は、ポーリングを「送りっぱなしの送信と、応答イベントによる進行」で行うと決めていた。この方式では、ポーリングの応答を TID だけで照合するので、他の要求の応答と区別しにくい。

同時に処理できる要求の数や応答の遅さは、無線 LAN アダプタやゲートウェイなど、ノードの通信部分によって決まることが多い。1 つのノードに複数の機器オブジェクトがあっても、通信部分は共通である。

## 決定

### 要求の直列化

- 機器への要求は、すべてノードごとの直列キューを通して送る。1 つのノードには、応答待ちの要求を同時に 1 つだけ持つ。
  - 対象は、setup の GET、INF_REQ、範囲の初期化の SetC、定期ポーリングと即時ポーリングの GET、呼び出し側の GET と SetC である。
  - ノード探索のマルチキャストと、INFC への応答（`0x7A`）は対象外とする。
- キューから取り出す順番は、優先度の高い順とし、同じ優先度では到着順とする。
  1. 呼び出し側の SetC
  2. setup の GET・INF_REQ・範囲の初期化の SetC、呼び出し側の GET
  3. ポーリングの GET
- 応答のタイムアウトは要求ごとに決め、キューで待っている時間は含めない。
- ポーリングも要求として応答を待つ。ADR-0005 の「送りっぱなしの送信と、応答イベントによる進行」は採用しない。

### setup の切り離しと並列化

- 受信イベントを処理するタスクは、キャッシュの更新と通知だけを行い、機器への要求を待たない。
- setup・INF_REQ・範囲の初期化は、ノードごとのタスクで行う。ノードの中では直列に、ノードをまたいでは並列に実行する。同時に setup するノード数に上限は設けない。
- setup では、まずメーカーコード（`0x8A`）を単独で読む。次に、デバイスクラスとメーカーコードから取得する EPC を決め、プロパティマップとともに取得する。メーカーコードを読み終えている場合（ADR-0006）は、最初の読み出しを省く。

### ADR-0005 から引き継ぐ決定

- 同時応答数の上限を探るのは setup だけとする。上限は機器オブジェクトごとに `HemsClient` が持つ。
- ポーリングは上限を探らない。既知の上限と組み合わせ制約による計画（`take_first_batch`）で分割する。
- ポーリングで要求がタイムアウトしたり、一部の EPC が欠けたりしても、その周期の中で再送や再分割はしない。次の周期に任せ、失敗した周期は生存確認とバックオフのために失敗として数える。

## 結果

- 1 つのノードに同時に複数の要求が届かなくなり、同時応答数に制約のある機器でも要求が衝突しない。
- 応答の遅いノードがあっても、ほかのノードの setup と受信処理は待たされない。ほかのノードのポーリングが、誤って失敗と数えられることもなくなる。
- 起動直後は、すべてのノードに setup の要求がほぼ同時に送られる。1 ノードあたりの要求は 1 つずつなので、負荷の形はノードをまたいだポーリングと同じである。
- 応答待ちの要求があるノードでは、SetC もその要求が終わるまで待つ。待ち時間は最大で、その要求のタイムアウトになる。
- ポーリングの応答は、送った要求そのものと照合される。応答時間には、受信イベントの処理の遅れが含まれなくなる。
- ADR-0005 はこの ADR で置き換える。ADR-0006 のうち「setup の並列化は追加しない」は、この ADR で変更する。ADR-0006 のその他の決定（setup の完了条件と、次の探索での再実行）は維持する。
- 全インスタンス宛て（インスタンスコード `0x00`）の GET は、引き続き範囲外とする。
