# 0002. 応答が著しく遅くなるため EPC 0x88 の自動取得を避ける

- ステータス：承認
- 日付：2026-10-24

## コンテキスト

パナソニック MKN7350S1 は、EPC 0x88（異常発生状態）を読み出すと応答が非常に遅くなる。[issue #105](https://github.com/sayurin/hems_echonet_lite/issues/105) で報告され、[調査後の対応](https://github.com/sayurin/hems_echonet_lite/issues/105#issuecomment-5770373684)として 0x88 の取得をやめた。

生存確認のために追加した読み取りが応答遅延やタイムアウトの原因になると、正常に値を取得できる機器まで無応答と判定してしまう。

## 決定

- 機器の自動情報取得や生存確認のために EPC 0x88 を読み出さない。
- 生存確認は、通常の取得対象に対する応答を利用する。確認のためだけに 0x88 を追加しない。
- 取得経路をリファクタリングするときも、この回避策を維持する。

## 結果

- 0x88 の読み出しによる著しい応答遅延を避けられる。
- 自動取得では 0x88 による異常発生状態を得られない。プロパティマップに掲載されていることだけを理由に取得対象へ追加してはならない。
- この ADR は自動取得方針の記録であり、公開 GET API で呼び出し元が明示した EPC を強制的に除去する仕様は追加しない。
