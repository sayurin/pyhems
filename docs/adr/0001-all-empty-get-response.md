# 0001. 同時応答数の上限の決め方と、全 EPC が PDC=0 の GET 応答の扱い

- ステータス：承認
- 日付：2026-10-24

## コンテキスト

ECHONET Lite の仕様では、GET 応答で PDC=0（EDT が空）の EPC は「その EPC に未対応」という意味である。また、機器が一度に処理できる数を超える EPC を要求された場合は、先頭から処理できた EPC だけを返す（OPC が要求数より少ない部分応答）。

ところがノクリア AS-R56E2W（`manufacturer_code=0x00008A`、`product_code=AS-R56E2W`）は、同時応答数の上限を超えると、要求したすべての EPC に PDC=0 を返す。このとき OPC は要求数と同じである。[報告スレッド](https://github.com/sayurin/hems_echonet_lite/discussions/3#discussioncomment-18278717)では、48 EPC の要求は全 EPC が PDC=0 の応答となり、24 EPC の要求は正常に値が返った。仕様どおりに解釈すると、この機器の EPC はすべて未対応ということになり、機器を制御できなくなる。

以前の実装は、全 EPC が PDC=0 の応答を受けた時点で `ceil(n/2)` を上限として記録していた。そのため、半減した要求も全 EPC が PDC=0 だった場合は上限が既知として扱われ、それ以上は分割せず、すべて未対応と解釈していた。

## 決定

同時応答数の上限は機器オブジェクト（ノード ID と EOJ の組）ごとに管理し、「未確定」と「確定（値 c）」のどちらかの状態を持つ。

### 上限の確定

上限は、有効な応答を受け取った時点で、機器がその応答で処理した EPC 数（応答の OPC）とする。分割しただけでは確定しない。次の場合が該当する。

- **PDC>0 の検出**：要求した n 個の EPC がすべて応答に含まれ（OPC = n）、そのうち 1 つ以上が PDC>0 なら、上限を n とする。
- **仕様どおりの部分応答**：要求した n 個のうち先頭から m 個（0 < m < n）だけが応答に含まれていたら（OPC = m）、上限を m とする。応答に含まれなかった EPC は改めて要求する。
  - 要求数 n を上限にはしない。機器は n 個を処理できないことを部分応答で示しているので、n で送り続けると毎回部分応答になる。
- **分割探索中の 1 EPC の正常応答**：PDC=0 でも、その EPC が未対応であることを示す正常応答として扱い、上限を 1 とする。PDC>0 を待ち続けない。
- 上限が確定している場合は、より小さい値が観測されたときだけ縮める。引き上げはしない。
- 分割探索を始める前の 1 EPC の要求（メーカーコードの単独取得など）は、上限の観測に使わない。

### 全 EPC が PDC=0 の応答

- **上限が未確定**で、要求した EPC が 2 個以上、そして応答した**すべての** EPC が PDC=0 だった場合：
  - 同時応答数の上限を超えたと判断する。
  - 上限は未確定のまま、同じ EPC 群を `ceil(n/2)` 個ずつに分けて再送する。
  - 半減した要求でも全 EPC が PDC=0 なら、2 EPC 以上である間はさらに半減する。PDC>0 を含む応答、仕様どおりの部分応答、または 1 EPC の正常応答が得られた時点で、上記の規則に従って上限を確定する。
- **上限が確定している**場合、または要求した EPC が 1 個の場合は、仕様どおり PDC=0 の EPC を未対応として扱う。

## 結果

- バグのある機器でも、分割した後の応答から実際の値を取得でき、そのときの要求数が上限になる。報告された機器では、48 → 24 で値が返り、上限は 24 になる。
- 上限が未確定の機器で、要求した EPC が本当にすべて未対応だった場合も、分割して再送することになる。そのぶん余計な通信が発生する。最終的に 1 EPC の要求で PDC=0 の正常応答を受けると、上限は 1 に確定し、残りも 1 EPC ずつ取得する。
- 上限が確定した後は、すべてが PDC=0 の応答でも分割しない。同じ機器に対して分割を繰り返さないためである。
- 記録した上限を引き上げる仕組みはない。
