# 0006. 不完全な setup を次の探索でやり直す

- ステータス：承認
- 日付：2026-10-24

## コンテキスト

メーカーコードを取得できても、プロパティマップを取得できないまま機器を登録すると、以後の探索では既知の機器としてスキップされる。定期ポーリングの対象も決められず、初期取得の失敗から回復できない。

setup の同一要求のリトライを廃止し、1 EPC の要求がタイムアウトしたら当該機器の登録をあきらめる（ADR-0004）ため、後からその機器の setup をやり直せる機会を設ける。一方、正しく取得した要素数 0 のマップを取得失敗とみなしてはならない。

## 決定

- ADR-0004 による当該機器の取得打ち切り（1 EPC の要求のタイムアウト）は、不完全な setup として扱う。当該機器は登録せず、他の機器の setup は継続する。
- setup の完了条件を「有効なメーカーコードと、有効な 9D・9E・9F のプロパティマップを取得したこと」とする。
- マップの有効性は EPC 集合が空かどうかではなく、EDT の取得と形式の検証で判定する。例えば `EDT=00` は有効な空マップ、PDC=0 はマップ未取得である。
- 任意項目の製品コード、製造番号、監視対象 EPC の一部の未取得だけでは setup を失敗としない。
- 完了条件を満たさなければ、警告に不足・不正な EPC を記録し、通常の機器登録や追加通知を行わない。処理中の印は必ず解除する。
- 次に同じ機器を含むインスタンスリストを受け取ったら setup を再実行する。その場でのリトライループや新しい再試行タイマーは設けない。
- 有効なメーカーコードとバッチ学習状態は保持し、次回の setup で再利用する。機器状態を破棄する際の既存のライフサイクルには従う。

## 結果

- 一時的な無応答で永久に不完全な機器が登録されることを防ぎ、次の探索で回復できる。
- 必須情報を継続して返さない機器は登録されず、探索のたびに setup が試みられる。その状況は警告ログに表れる。
- 部分的な機器状態の公開、既存登録の動的な置換、setup の並列化は追加しない。
