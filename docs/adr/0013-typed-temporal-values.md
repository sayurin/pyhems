# 0013. 日時の通信形式と意味を分離して型付きの値を返す

- ステータス：承認
- 日付：2026-11-03

## コンテキスト

MRA の `time` は時刻と時間量の両方に使われている。型やサイズ、
`maximumOfHour` だけでは意味を判別できず、24 時間未満の時間量も存在する。
`date`、`date-time` と合わせて、利用者が意味を失わずに読み書きできる必要がある。

既存の単体定義は日時の意味や精度を表現できない。
日時と特殊状態を選択する単純な `oneOf` では、幅が一致するだけでなく
正常値の妥当性と特殊状態の完全一致を検査する必要がある。
今回の対象は単体日時とその単純な `oneOf` に限定し、構造内日時は扱わない。

根拠は同梱 MRA 1.3.2 の日時定義と MRA Guidebook 1.2.0 の
date / date-time / time の定義である。

## 決定

- 通信形式と意味を分離する。`EntityDefinition.temporal` に意味とサイズを保持し、
  対応する単体 `time` をクラス・EPCで明示分類する。
  名称や値から実行時に推測せず、未分類・重複・存在しない分類は生成エラーとする。
- 正常値は暦日を `datetime.date`、時刻を naive な `datetime.time`、
  時間量を `datetime.timedelta`、日時を naive な `datetime.datetime` として返す。
  機器の通信値には timezone がないため、ライブラリでは付与しない。
- date は 4 バイト、time は 2 / 3 バイト、date-time は 6 / 7 バイトを扱う。
  明示サイズを優先し、省略時はそれぞれ 4 / 3 / 7 とする。
  その他の部分サイズは生成エラーとし、不完全な値を完全な日時として返さない。
- 分・秒は 0..59、暦日はカレンダーとして検証する。時の上限は既定 23 とし、
  duration では明示された `maximumOfHour` を適用する。
  時バイトが `FF` という理由だけで特殊値にしない。
- encode は型、範囲、通信精度を検査し、負の時間量、timezone 付きの機器値、
  表現できない秒・microsecond などを `ValueError` とする。丸めない。
- codecは通信精度を`resolution`、durationの正常値上限を`maximum_duration`として
  `timedelta`で公開する。利用側は表示単位へ変換し、通信形式の判断・範囲検査は重複しない。
- 単体 `oneOf` は正常日時1種と同じ幅の特殊状態だけを扱う。
  特殊状態は既存の `enum_values` に保持する。
  正常値の妥当性と特殊状態の完全なバイト列を照合し、
  既存codec同様、encodeではアクセス権を検査しない。
  書き込み可否は利用側がプロパティのwritableで判断する。
  状態別アクセス情報と再帰的な値ツリー属性は追加しない。
- 既存の構造化定義・デコードは維持し、object / array 内の日時変換は追加しない。
- 明示された特殊状態は MRA のキー文字列、不正値は `None` として返す。
  非対応値と不正値は診断可能にし、正常な日時を捏造しない。
- 単体temporal値と、同幅の明示stateのみを追加候補とする単純な`oneOf`を扱う。
  temporal候補とstate以外の候補が混在する`oneOf`はプロパティ全体を除外する。
  対応形状でないtemporalプロパティを、通常のstateや構造化定義として再解釈しない。
  EPC、メーカー、level base値などの個別条件ではなく、MRAの候補構造で判定する。
- MRA 外の特殊符号・範囲の補完、汎用構造体の部分更新・encode、
  機器の時計の自動設定は追加しない。
- ノードプロファイルの日時定義は registry の対象外とする。

## 結果

- 時刻と時間量を Python の型でも区別でき、24 時間以上の時間量も表現できる。
- MRA 更新で新しい time が増えた場合、人間による分類が必要になる。
- 従来単体codecで扱えなかった日時の正常値が型付きの値になる。
  数値・状態・既存の構造化計測値の契約と識別子は維持する。
- 複雑な`oneOf`を部分的なtemporal定義として公開しない。
  洗濯乾燥機の通常時間・auto状態・相対levelが混在する時間設定は、
  プロパティ単位で除外される。
- 対応可能なtemporal `oneOf`に新しいstate候補が追加された場合は引き続き生成対象となる。
- 正常日時だけを扱う利用者は、戻り値の型と定義の意味を確認する必要がある。
