# 0003. パナソニックの 0x0287 では EPC 0xB3 と 0xB7 を別の GET に分ける

- ステータス：承認
- 日付：2026-10-24

## コンテキスト

デバイスクラス 0x0287 の EPC 0xB3 と 0xB7 は、値のサイズが大きくなりやすい。

[issue #116](https://github.com/sayurin/hems_echonet_lite/issues/116) のパナソニック MKH73001S1 は、[調査](https://github.com/sayurin/hems_echonet_lite/issues/116#issuecomment-5973614908)から応答サイズに 255 バイトの制限があると推測されている。このため、両方の EPC を 1 回の応答に含められない。255 バイトはこの機器について推測された制約であり、ECHONET Lite 全般の制限としては扱わない。

これは EPC の個数ではなく値のサイズと組み合わせによる制約である。ADR-0001 の同時応答数探索だけに任せると、失敗を EPC 数の上限超過と誤解し、送信上限を極端に小さくしてしまう。

## 決定

- メーカーコード `0x00000B`（パナソニック）、デバイスクラス `0x0287` の組に対し、1 回の GET に 0xB3 と 0xB7 の両方を含めない。
- 片方の取得を省略するのではなく、別の GET に分け、両方を取得する。
- 制約は `get_batch_policy` の `incompatible_pairs` で表現し、同時応答数の上限とは独立に適用する。
- setup、定期ポーリング、即時ポーリング、公開 GET API のいずれも、メーカーとクラスが該当するときは同じ制約を守る。
- 他のメーカーやクラスへ、この禁止ペアや 255 バイトの制約を一律に適用しない。

[対応の記録](https://github.com/sayurin/hems_echonet_lite/issues/116#issuecomment-5973672229)に示された既存ポリシーを、再設計後も維持する。

## 結果

- 大きな 2 つの値を同時に要求することによる取得失敗と、同時応答数の過小評価を避けられる。
- 同時応答数に余裕があっても、少なくとも両 EPC は別の要求になる。
- 任意の EPC の応答サイズを予測する汎用のバイト数制御は導入しない。
